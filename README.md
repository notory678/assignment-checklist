# 과제 제출 누락 방지 도우미

한국어 과제 공지를 정리하고 제출 준비를 확인하는 Cloud Programming 개인 프로젝트입니다. 공지에서 체크리스트 후보를 추출하고, 사용자가 확인한 항목과 원문 근거, 완료 상태를 PostgreSQL에 저장합니다.

현재 구현 범위와 구조, 실행 방법, 검증 결과는 [개발 문서](docs/development.md)에 정리했습니다.

2026년 11월 12일 평가 기준에 맞춰 사용자 시나리오, 요구사항별 완료 기준, 변경 이유와 테스트 개선 기록을 보강했습니다. 같은 날 별도 시험 환경에서 실행한 [49개 검사 결과](docs/test-evidence/2026-11-12-unittest.txt)도 함께 제공합니다.

2026년 11월 13일에 비고 항목, 저장한 항목 수정, 완료 항목 강조, 기존 공지에 추가 공지 붙이기, Groq PDF 페이지 추천, 항목·공지 삭제를 추가했고 검사는 69개로 늘었습니다. 아래 [11월 13일 추가 기능](#11월-13일-추가-기능)을 참고하세요.

## 로컬 실행

Docker Desktop을 열고 프로젝트 폴더의 터미널에서 실행합니다. 기본 AI 연결은 Groq API이며, 로컬 AI는 예비 기능으로 사용할 수 있습니다.

```bash
docker compose up --build -d --wait
```

맥에서 `docker` 명령을 찾을 수 없다면 터미널에서 `export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"`를 실행합니다. 8000번 포트를 사용 중이라면 `APP_PORT=8001 docker compose up --build -d --wait`로 실행하고 주소의 포트도 `8001`로 바꿉니다.

## 사용 방법

1. [과제 체크리스트](http://127.0.0.1:8000/)를 열어 제목과 공지 본문을 입력하고 **공지 저장**을 누릅니다. PDF가 있다면 아래 **PDF로 등록**을 이용합니다.
2. 상세 화면에서 **체크리스트 자동 생성**을 누릅니다. Groq API 키를 설정하면 API로 추출합니다. 키가 없으면 규칙 기반 추출을 사용하며, 준비된 로컬 AI도 별도 버튼으로 선택할 수 있습니다.
3. 결과 화면에서 원문과 비교하며 이름·근거를 수정합니다. 제외할 항목은 선택을 해제하고 **선택한 항목 저장**을 누릅니다.
4. **공지에 명시**와 **준비 제안**을 구분해 보여줍니다. 제안은 처음에 선택되지 않으며 필수 조건으로 취급하지 않습니다. 날짜가 없으면 제출 기한을 **미기재**로 표시합니다. 날짜를 계산하거나 연도를 추측하지 않습니다.
5. 항목 왼쪽의 체크 버튼을 누르면 완료 상태를 저장합니다. 다시 누르면 완료를 해제합니다. **공지 목록**으로 돌아가 저장한 공지를 다시 열 수 있습니다.
6. 각 항목의 **주소·메모 추가**를 열어 제출 주소와 준비 메모를 입력하고 **주소·메모 저장**을 누릅니다. 저장한 내용은 **내가 준비한 내용**에 표시되며, **주소·메모 수정**으로 바꿀 수 있습니다.

상세 화면의 **항목 추가**로 직접 입력할 수도 있습니다. **근거 문구**에는 공지 원문의 해당 문장을 그대로 복사합니다.

후보를 생성하는 것만으로 체크리스트가 바뀌지 않습니다. 선택한 항목은 한 번에 저장하며 같은 제목·근거·종류의 항목은 중복 추가하지 않습니다. 검토 중인 결과도 DB에 보관하므로 주소를 다시 열어 이어서 확인할 수 있습니다.

앱 시작 시 필요한 테이블을 확인하고 생성하므로 기존 PostgreSQL 볼륨에서도 같은 실행 명령을 사용합니다. 공지와 체크리스트는 앱과 DB를 내렸다 올린 뒤에도 볼륨에 보관됩니다.

## 제출 주소와 준비 메모

체크리스트마다 웹사이트·제출물·기록 문서의 주소와 준비 메모를 함께 저장합니다. 예를 들어 배포 주소 항목에는 실제 서비스 주소를, 보고서 항목에는 파일 위치를, 시연 항목에는 시연 순서를 적을 수 있습니다. 두 입력란 모두 선택사항이며 주소만 또는 메모만 저장할 수도 있습니다. 두 칸을 비워 저장하면 기존 내용을 지웁니다.

주소는 `http://` 또는 `https://`로 시작하는 웹 주소를 최대 2,048자까지 지원합니다. 로그인 정보가 포함된 주소는 저장하지 않습니다. 파일 경로는 메모에 적습니다. 메모는 줄바꿈을 포함해 최대 4,000자이며, 화면에서 코드로 실행하지 않고 텍스트로 표시합니다. 저장한 주소는 새 탭에서 열 수 있지만 앱이 주소에 접속하거나 정상 동작을 자동 판정하지는 않습니다.

서버에서 잘못된 주소나 길이 초과를 거절하면 입력한 두 값을 수정 화면에 유지하고, 저장되어 있던 주소·메모는 변경하지 않습니다. 두 값은 한 번에 저장하며 완료 상태·항목 이름·원문 근거·PDF 페이지 정보와 별도로 관리합니다. 저장 후 새로고침하거나 공지를 다시 열어도 유지되고, 체크리스트를 다시 추출해 같은 항목이 중복 제외되어도 준비 내용은 보존합니다. AI 추출 요청에는 공지 제목과 본문만 보내므로 주소·준비 메모는 포함되지 않습니다.

## PDF 공지 등록

1. 첫 화면의 **공지 PDF 파일**에서 파일을 선택하고 **PDF 본문 미리보기**를 누릅니다.
2. 페이지별 텍스트를 원본과 비교하고 공지 제목을 입력합니다. 강의 자료 전체를 분석할 필요 없이 과제 안내가 있는 페이지만 선택할 수 있습니다.
3. **선택한 페이지로 공지 저장**을 누르면 기존 상세 화면으로 이동합니다. 이때까지 외부 AI 호출은 없습니다.
4. **체크리스트 자동 생성**으로 Groq 또는 로컬 AI를 이용하거나, **기본 추출 사용**을 선택합니다. 기존과 동일하게 검토 후 선택한 항목을 저장합니다.
5. 원문 근거 옆의 **PDF N페이지**를 누르면 해당 페이지의 추출 텍스트로 이동합니다. 직접 추가한 항목과 제출 기한에도 근거 페이지가 표시됩니다.

무료 오픈소스 [pypdf](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)로 서버에서 텍스트를 읽습니다. 글자를 선택할 수 있는 PDF만 지원하며, OCR·표 구조 복원·이미지 해석은 포함하지 않습니다. 최대 5MB·50페이지·전체 추출 150,000자, 선택한 본문은 30,000자까지입니다. 긴 본문은 AI 서비스별 입력·무료 사용 한도에 걸릴 수 있으니 필요한 페이지만 골라 주세요. 페이지나 본문을 조용히 잘라 저장하지 않습니다.

스캔본처럼 읽을 텍스트가 전혀 없는 파일, 암호화된 파일, 손상된 파일은 안내와 함께 거절합니다. 일부 페이지에 텍스트가 없으면 미리보기와 저장한 공지에 경고를 남깁니다. 표·다단 문서는 읽는 순서가 달라질 수 있으므로 저장 전에 원본을 확인해야 합니다. PDF 파싱은 별도 프로세스에서 시간 제한과 Linux 자원 상한을 적용합니다.

페이지 번호는 PDF 내부의 물리적 순서이며, 문서에 인쇄된 쪽 번호와 다를 수 있습니다. 번호는 AI 응답으로 받지 않고 저장한 원문에서 근거의 정확한 위치를 찾아 계산합니다. 같은 문구가 여러 페이지에 있으면 모두 표시하고, 페이지를 가로지르는 인용도 연결된 페이지를 표시합니다. PDF에서 추출한 텍스트는 페이지 번호의 일관성을 위해 이 화면에서 수정하지 않습니다. 원문을 고쳐 붙여넣기로 등록한 공지에는 PDF 페이지 번호를 붙이지 않습니다.

PDF 파일 자체는 보관하지 않고 파일명·페이지별 텍스트·선택한 본문만 PostgreSQL에 저장합니다. 미저장 미리보기는 24시간 동안 다시 열 수 있고, 다음 PDF 업로드 때 기간이 지난 미저장 자료를 정리합니다. 중복 클릭이나 동시에 저장해도 같은 미리보기에서 공지를 여러 개 만들지 않습니다. 이 앱은 현재 개인 로컬 사용을 전제로 하며 계정별 접근 분리는 아직 없습니다.

## 11월 13일 추가 기능

- **비고 항목**: 공지의 예시·선택·권장·불필요·추후 안내 문장은 필수로 만들지 않고 **비고 · 선택·예시·참고**로 따로 보여 줍니다. 원문 문장을 근거로 붙이며, 기본으로 선택하지 않고 필요할 때 골라 저장합니다. 원문에 없는 비고는 제외합니다.
- **저장한 항목 수정**: 상세 화면의 **항목 수정**에서 이름과 근거를 바꿀 수 있습니다. 근거는 다시 원문과 대조하고, 실패하면 아무것도 바꾸지 않습니다. 완료 상태와 주소·메모는 그대로 유지합니다.
- **완료 항목 강조**: 완료한 항목은 칸 전체가 강조 색으로 바뀌고 **완료** 배지가 붙습니다.
- **추가 공지 붙이기**: 공지 등록의 **등록 방식**에서 기존 공지를 고르면 본문 끝에 `[추가 공지] 제목`으로 덧붙입니다. 새 공지를 만들지 않으며 기존 체크리스트와 완료 상태는 그대로입니다. 합친 본문은 30,000자까지입니다. 이후 **체크리스트 자동 생성**을 다시 실행하면 새 조건을 후보로 볼 수 있고, 이미 있는 항목은 중복 저장하지 않습니다.
- **PDF 페이지 추천 (Groq)**: PDF 미리보기에서 **AI 페이지 추천 (Groq)**을 누르면 읽은 페이지 텍스트를 Groq로 보내 과제 조건이 있는 페이지, 요약, 근거 문장을 받습니다. 근거 문장이 실제 그 페이지에 없거나 없는 페이지 번호이면 추천에서 뺍니다. 추천 페이지만 미리 선택되며 저장 전 사용자가 확정합니다. 무료 한도를 위해 전체 12,000자 안에서 페이지마다 앞부분만 보내고 그 사실을 안내합니다. 버튼을 누르기 전에는 외부로 보내지 않으며, 실패해도 다른 서비스로 전환하지 않고 직접 선택할 수 있습니다.
- **삭제**: 항목마다 **항목 삭제**로 그 항목과 완료 상태·주소·메모를 지울 수 있습니다. 상세 화면 위의 **공지 삭제**는 공지와 체크리스트 전체를 지웁니다. 두 삭제 모두 펼친 뒤 버튼을 한 번 더 눌러야 실행되며, 다른 공지의 항목은 지울 수 없고 되돌릴 수 없습니다.
- **공지 본문 상한**: 새 공지 본문은 30,000자까지 저장합니다. 넘으면 자르지 않고 안내합니다.

## API에서 공지 시험하기

브라우저에서 [API 문서](http://127.0.0.1:8000/docs)를 열고 `POST /assignments`의 **Try it out**을 누릅니다. 아래 예시를 입력하고 **Execute**를 누르면 `201` 응답에 저장된 공지의 `id`가 표시됩니다.

```json
{
  "title": "클라우드 프로그래밍 프로젝트",
  "body": "배포 주소를 포함하세요.\n발표 자료를 준비하세요."
}
```

- `GET /assignments`는 최근 공지부터 제목과 ID, 등록 시각을 보여줍니다.
- `GET /assignments/{assignment_id}`에 저장된 ID를 넣으면 본문까지 조회합니다. 없는 ID는 `404`를 반환합니다.
- 공백뿐인 제목이나 본문은 `422`로 거절합니다. 정상 본문의 줄바꿈은 그대로 저장합니다.

## 추출 방식과 한계

- **기본 자동 추출**: 외부 전송 없이 PDF 보고서, 배포 주소, 정상·실패 시연, AI 사용 내역, 발표 자료, 소스 코드, 저장소 주소, 영상, 압축 파일 같은 정해진 표현을 찾습니다. 그 밖의 짧은 제출·준비 문장도 후보로 보여줍니다.
- 선택·불필요·예시·추후 안내가 포함된 문장은 기본 추출에서 제외합니다. 한 문장에 필수와 선택 조건이 섞이면 필수 항목도 누락될 수 있습니다. 문장 맥락과 표·복잡한 조건은 사용자가 원문과 비교해야 합니다.
- 자동 추출 본문은 30,000자, 결과는 최대 40개입니다. 원문에 없는 근거는 제외하고, 검토 중 근거를 수정한 경우에도 저장 직전에 원문 일치를 다시 확인합니다. 문구 일치만으로 제목의 의미까지 검증하지는 않습니다.

## 기본 연결: Groq Free API

[Groq의 Free 플랜](https://console.groq.com/docs/rate-limits)을 사용합니다. 기본 모델은 `openai/gpt-oss-20b`이며 [엄격한 JSON Schema 출력](https://console.groq.com/docs/structured-outputs)을 지원합니다. 같은 모델 이름이라도 이용하는 서비스의 계정 플랜에 따라 비용 조건이 달라집니다. 비용 없이 진행하려면 Groq 계정을 **Free 플랜으로 유지**합니다. 앱은 계정의 결제 플랜을 판별하거나 자동 변경하지 않습니다.

1. [Groq Console](https://console.groq.com)에 로그인합니다.
2. [API Keys](https://console.groq.com/keys)에서 프로젝트용 키를 발급합니다. 유료 Developer 플랜으로 업그레이드하지 않습니다.
3. 프로젝트의 `.env`에 아래 값을 입력합니다. 기존 `.env`가 있으면 덮어쓰지 않고 해당 값만 수정합니다. 실제 키는 로컬 편집기에서 `GROQ_API_KEY`에 입력하고 채팅·Git에 올리지 않습니다.

```ini
AI_PROVIDER=groq
GROQ_API_KEY=
GROQ_MODEL=openai/gpt-oss-20b
```

4. `APP_PORT=8001 docker compose up --build -d --wait`로 앱을 실행합니다. 설정만 바꿀 때는 `--build`를 생략할 수 있습니다.
5. 공지 화면의 **무료 API · Groq**를 확인하고 **체크리스트 자동 생성**을 누릅니다. 키가 없으면 화면에 키 설정이 필요하다고 표시하며 기본 추출로 동작합니다. 이 표시는 설정 유무를 뜻하고 실제 인증 성공은 요청할 때 확인합니다.

공지 제목과 본문이 Groq에 전송됩니다. Free 플랜에는 분당·일별 요청/토큰 한도가 있으며 실제 계정의 [Limits](https://console.groq.com/dashboard/limits) 화면에서 확인합니다. 한도 초과(429), 키 오류, 응답 오류를 구분해 안내합니다. 자동 재시도나 다른 외부 서비스로의 자동 전환은 하지 않습니다. 오류가 나면 사용자가 **로컬 AI로 생성** 또는 **기본 추출 사용**을 선택할 수 있습니다.

요청 주소는 `https://api.groq.com/openai/v1/chat/completions`이며 JSON Schema 응답을 서버에서 다시 검증합니다. 기존 HF 및 AI Gateway 키는 더 이상 사용하거나 앱 컨테이너에 전달하지 않습니다. API 키가 없는 검증 환경에서는 Groq 응답을 모의 처리하며, 실제 API 연결은 본인 키 설정 후 확인합니다.

## 예비 기능: 무료 로컬 AI

외부 API 토큰 없이 맥에서 [Ollama](https://docs.ollama.com/macos)와 [qwen3:4b](https://ollama.com/library/qwen3:4b)를 실행합니다. 외부 AI API 요금은 없으며, 컴퓨터의 메모리와 전력을 사용합니다. 검증 환경은 Apple M1 · 메모리 16GB입니다.

최초 한 번 Python 3.13으로 실행합니다. 공식 Ollama 0.40.16 실행 파일과 약 2.5GB의 모델을 다운로드합니다.

```bash
python3.13 scripts/local_ai.py setup
APP_PORT=8001 docker compose up --build -d --wait
```

설치 파일의 SHA-256을 확인한 뒤 실행하며, 실행 파일·모델·로그는 Git과 Docker 빌드에서 제외되는 `.local-ai/`에 보관합니다. 설치 도우미는 Ollama의 클라우드 기능을 비활성화하고 `127.0.0.1:11434`에서만 서버를 엽니다. macOS 전역 설치나 자동 시작 등록은 하지 않습니다.

컴퓨터를 재시작한 뒤에는 다음 두 명령으로 다시 켭니다.

```bash
python3.13 scripts/local_ai.py start
APP_PORT=8001 docker compose up -d --wait
```

상태 확인은 `python3.13 scripts/local_ai.py status`, 종료는 `python3.13 scripts/local_ai.py stop`입니다. AI를 종료해도 웹앱의 기본 추출과 저장한 체크리스트는 사용할 수 있습니다.

`.env`의 연결 설정은 다음과 같습니다. Docker Desktop은 `host.docker.internal`을 통해 맥에서 실행 중인 Ollama에 연결합니다.

```ini
OLLAMA_BASE_URL=http://host.docker.internal:11434
OLLAMA_MODEL=qwen3:4b
```

Python으로 앱을 직접 실행할 때는 `OLLAMA_BASE_URL=http://127.0.0.1:11434`로 설정합니다. `OLLAMA_MODEL=`로 비우면 기본 추출만 사용합니다. 기존 HF 토큰이나 유료 AI Gateway 설정은 사용하지 않으며 앱 컨테이너에도 전달하지 않습니다.

상세 화면에서 **로컬 AI로 생성**을 누릅니다. 로컬 AI를 기본으로 쓰려면 `.env`에 `AI_PROVIDER=ollama`를 설정합니다. 검토 화면에 **로컬 AI 추출 결과**가 표시되며 항목·근거를 수정해 저장할 수 있습니다. 실패하면 오류를 보여주고 **기본 추출 사용**을 선택할 수 있습니다. 유료 API로 자동 전환하지 않습니다.

로컬 AI는 본문 최대 6,000자와 보수적인 입력 크기 검사를 적용합니다. 16,384 토큰 문맥에서 출력 공간을 확보하기 위해 UTF-8 바이트 길이로 입력 상한을 확인하므로 한국어 공지는 6,000자보다 짧아도 나누어 등록해야 할 수 있습니다. 긴 공지를 임의로 잘라 분석하지 않습니다. 출력이 끝나지 않은 경우에도 저장하지 않고 오류를 안내합니다.

모델 응답은 Ollama의 [JSON Schema 구조화 출력](https://docs.ollama.com/capabilities/structured-outputs)을 사용하며, 원문 근거와 응답 형식을 서버에서 다시 검증합니다. 처음 실행하거나 모델을 다시 읽는 동안에는 시간이 더 걸릴 수 있습니다. 모델은 유휴 상태가 되면 메모리에서 내려갈 수 있습니다.

맥이 꺼지면 로컬 AI도 멈춥니다. 외부 클라우드에 웹앱을 배포할 때는 그 환경에서 AI를 실행할 위치와 자원을 별도로 정해야 합니다. 기존 AI 추출 결과는 그대로 읽을 수 있으며 새 결과에는 Groq 또는 로컬 실행 정보와 모델 이름이 함께 저장됩니다.

## 검증

의존성을 설치한 Python 환경에서 `python -m unittest discover -s tests -v`로 추출·PDF·웹 흐름 검사를 실행합니다. 웹 흐름 검사는 `CHECKLIST_TEST_URL`이 있을 때만 실행합니다. 이 검사는 해당 서버에 시험 공지를 생성하므로 별도 테스트 DB를 사용합니다.

Groq·로컬 AI 응답부터 검토·저장·완료 체크까지의 DB 통합 검사는 별도 테스트 DB에 연결된 앱 컨테이너에서 `CHECKLIST_DB_TESTS=1`로 활성화합니다. 이 검사는 실제 토큰 대신 모의 API 응답을 사용하며 외부 AI 요청을 보내지 않습니다.

실제 연결 검증에서는 예시 공지의 보고서 PDF·배포 주소·AI 사용 내역 3개 조건을 Groq에서 추출하고, 브라우저에서 검토·저장·완료 체크까지 확인했습니다. 같은 예시의 로컬 AI 추출도 확인했습니다. 사용자 공지를 외부 모델로 시험 전송하지 않고 별도의 합성 예시를 사용했습니다.

PDF 기능은 한글 원문·빈 페이지·암호화·손상·용량 및 페이지 수 제한, 페이지 선택과 동시 저장, 근거 페이지 계산, 편집 후 근거 위치 갱신을 검사합니다. 실제 브라우저에서도 합성한 3페이지 PDF를 업로드해 본문 확인 → 공지 저장 → Groq 추출 → 검토·저장 → 완료 체크·새로고침·페이지 링크 이동을 확인했습니다. 기존 공지 9개와 체크리스트 완료 상태의 보존도 확인했습니다.

주소·메모는 실제 HTTP와 별도 DB로 저장·수정·비우기, 선택 입력, 주소 형식·메모 길이 검증, 오류 시 기존 내용 보존, 다른 공지의 항목 변경 차단, 재추출 후 준비 내용 보존을 검사합니다. PDF 원문·페이지 정보와 완료 상태의 보존도 검사합니다. 실제 브라우저에서 예시 항목의 주소·메모를 저장하고 수정한 뒤 공지를 다시 열어 유지되는 것을 확인했습니다.

## 구현 순서

3. 스캔 PDF의 OCR을 검토하고 클라우드에 배포합니다.
